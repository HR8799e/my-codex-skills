# MATLAB 数模论文图

## 目标

让图服务于模型和结论，像参赛队员根据当前题目整理出的论文图，而不是套用统一的装饰模板。优先保证数据正确、信息清楚、论文尺寸下可读，再考虑美观。

“降低 AI 味”指减少模板化设计和教程式代码，使图形选择与数据含义一致。不要故意写乱代码、制造错误，也不要声称能够规避 AI 检测。

## 先判断图的任务

- **模型示意图**用于解释对象、结构或几何关系，可以保留少量必要名称、尺寸和箭头，但不要把所有部件都装进文本框。
- **计算结果图**用于展示数值、趋势和差异。尽量只保留数据、曲线或点、坐标轴、单位及必要图例，解释放到正文和图注。
- 用户给出优秀论文或参考图时，先观察其信息层级、比例和标注习惯，再结合当前数据复现表达方式，不机械照搬内容。

## 图形表达

- 默认不在绘图区内放标题；给出建议图题供用户放在论文图片下方。用户明确要求图内标题时再添加。
- 坐标轴名称和单位必须清楚。只有多组数据确实需要区分时才放图例。
- 结果图不逐点标名，不堆叠长说明、箭头、文本框、渐变、阴影和装饰图标。
- 默认采用黑、灰及线型区分；黑白难以辨认时使用少量低饱和颜色，不为了“高级感”强行统一配色。
- 网格默认关闭；读数确实需要时使用很淡的主网格，不添加密集次网格。
- 几何位置、轨迹和形状图保持真实横纵比例，通常使用 `axis equal`，除非比例压缩本身是需要说明的表达决定。
- 留白以论文单栏或双栏尺寸为准，避免图例遮挡曲线、字体过小和线条过细。

## 科学严谨性

- 只画真实输入数据或模型计算结果。示例数据必须明确说明是示例，不能伪装成题目结果。
- 局部放大、截断坐标轴、归一化、平滑或筛选数据时，至少在图中、代码短注释或建议图注中说明一处。
- 误差、置信区间和约束边界对结论有影响时保留，不能为了画面干净而删除。
- 多组曲线除了颜色外，尽量同时用线型或标记区分，保证黑白打印仍能阅读。

## 代码写法

- 默认交付一份可直接运行的 MATLAB 脚本；用户明确指定 Python 时服从用户，不同时输出两套重复代码。
- 一次性竞赛脚本优先从上到下写：数据或参数、计算、绘图、导出。只有重复计算或较长数学步骤确实需要时才定义函数。
- 变量名短而有题目含义，优先使用论文符号，如 `x`、`t`、`v`、`r`、`theta`、`err`。不要给简单局部量使用句子般的长名称。
- 注释只解释模型含义、特殊参数、局部放大或不明显的画图决定。不要写“读取数据”“开始画图”“保存图片”等复述代码的教程式注释。
- 不为一次性绘图添加配置类、日志、命令行参数、类型体系或多层通用封装。少量直接重复比配置表更直观时允许保留。
- 数据文件固定时使用简单相对路径，并让输出文件保存在脚本所在项目中容易找到的位置。

## 输出

MATLAB 默认同时保留高清位图和矢量图导出语句，文件名根据图的实际含义确定：

```matlab
exportgraphics(gcf,'result.png','Resolution',600);
exportgraphics(gcf,'result.pdf','ContentType','vector');
```

Python 绘图则同时保存 600 DPI PNG 和 PDF，并设置 `bbox_inches='tight'`。输出前确认白色背景、字体、线宽和标记在论文缩放后仍清楚。

## 交付与验证

1. 给出完整代码，并简短说明输入数据、输出文件和建议图题。
2. 当前环境能运行对应软件时，实际执行并查看图片，重点检查坐标、图例、比例、中文字体和留白。
3. 当前环境没有 MATLAB 时，明确说明 `.m` 文件尚未经过 MATLAB 实机运行，不要把静态检查说成运行成功；请用户运行后根据报错或截图继续调整。
4. 交付前删去与当前图无关的装饰、封装和注释，但不得删去单位、误差说明或影响解释的标注。
